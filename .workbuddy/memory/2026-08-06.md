## 实现「白话文模式」功能（文言文 → 现代白话）
游戏《抉择千秋 / Choice of History》新增一键/设置项开启的「白话文模式」，将全部面向用户的文言文案实时替换为现代白话。

### 关键事实与决策

- 发现 index.html 中已存在一个**半成品/重复的** baihua 桩函数块（BK/bhOn/bhCache/bhFetchField/updateBhUI/toggleBaihua 等无渲染接入），已删除该死代码，仅保留完整实现。

## 第二轮代码审查：修复结算/死亡/AI 解析类 bug（index.html）
上一轮修了"选人即崩"（缺失 BK/bhOn 等函数）。本轮聚焦上次无头测试未跑到真值的 AI/死亡路径，新增发现并修复：

1. **选项可重复点击结算（致命玩法 bug）**：出结果后 `event-panel` 不隐藏，玩家点第二个选项会再次扣加数值、重复写历史、曲线多一个点。修复：`makeChoice` 加 `currentEvent._resolved` 防护。
2. **被动健康衰减致死不触发结局（致命逻辑 bug）**："健康=0 皇帝驾崩"只在选项结算后检查；自然衰减磨到 0 时无人检查，皇帝不死、游戏无限续。修复：`nextMonth` 被动衰减后对 `state.stats.health<=0` 调用 `endGame("驾崩")` 并 return。
3. **驾崩竞态**：死亡靠 1200ms 定时才置 `cohEnded`，其间点"推进下月"仍可死后续玩。修复：`renderOutcome` 死亡分支**同步**置 `cohEnded=true`（结局屏仍延迟 1200ms 显示）；另给 `endGame` 加 `if(cohEnded) return` 防多路径重复进入。
4. **AI JSON 解析脆弱**：模型用 ```` ```json ```` 围栏或前后加说明文本时 `JSON.parse` 直接抛错，每次 AI 生成都静默降级成预设事件。修复：新增 `safeParseJSON`（去围栏 + 截取首尾 {} / []），`callAI` 改用之。
5. **fetch 超时未清除** + **choices 容错**：`callAI` retry 循环把 `t` 提到 try 外并在 catch 清 `clearTimeout(t)`；`loadEvent`/`pregenerateMonths` 对 AI 返回的字符串型 choices 兜底为 `{text, hint}`。

### 验证方式

- 临时验证脚本（_harness2.cjs/_run2.js）已清理。

## 第三轮代码审查：修复科技树存档回归 + 数值展示不一致
本轮聚焦科技树接入后的回归与展示层正确性（已通读 index.html 全量 + tech_engine.js）。

### 修复的 bug
1. **读档后科技树档案丢失（重要回归）**：`doLoad` 重建 state 后未调用 `applyTechProfile()`，导致读档后 `state.techProfile` 为 null。后果：科技查看器显示"数据未加载"、科技阻力事件因 `aheadCount===0` 不再触发、AI 叙事丢失科技档案。修复：`doLoad` 构建 state 后、`enterMonth()` 前调用 `applyTechProfile()`（幂等，按朝代预设重建 ownedTechs/techProfile 并注入超前科技加成）。
2. **数值变化展示与实际生效不一致（中）**：`applyOutcome` 对 `state.stats` 应用时会把单项 `clamp` 到 ±limit（常规 10 / 危机 12~17），但 `sc` 对象保持 AI 原值（可能 ±15），`recordHistory`/`renderOutcome` 用未截断的 `sc` 显示"变化 +15"而实际只加 +10。修复：把截断后的 `v` 写回 `sc[k]`，使变化面板与真实数值一致（`fallbackOutcome` 本就一致，仅 AI 路径有此脱节）。
3. **techBaseStats 快照顺序（次要）**：`applyTechProfile` 的 `techBaseStats` 注释称"注入前基线快照"，但赋值发生在 ahead 加成注入之后。修正：先记录快照再注入（目前无代码消费，仅保证语义正确，便于将来科研重算）。

### 本轮未改（确认非 bug / 设计如此）
- `_techResistArmed` 在 `shouldTriggerTechResist` 中写入但无读取者（死状态，无害，未动）。
- 硬编码甲类皇帝（E_QIN_SHIHUANG 等）的事件入库时未经 `normalizeEvent`，其事件 `id` 缺省、靠 title 去重；与内置/在线皇帝路径一致，无崩溃。
