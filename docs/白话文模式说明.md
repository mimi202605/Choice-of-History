# 白话文模式（文言文 → 现代白话）使用与开发说明

《抉择千秋 / Choice of History》内含大量文言文文案：皇帝的历史评价、背景介绍、时代背景、
以及每个历史事件的标题、描述、五个选项与史实结局，甚至 AI 实时生成的事件也默认要求「文言或半文言」。

**白话文模式** 让没有文言基础的玩家也能完全理解全部介绍文字与可选项内容：
开启后，游戏内所有面向用户的文言文案会被实时替换为通俗易懂的现代白话文；关闭则恢复原文言文。

---

## 一、如何开启

两种方式，效果一致、全局同步：

1. **一键切换（推荐，游戏内即时）**
   - 游戏主界面（右上角按钮 `白话：关 / 白话：开`）
   - 「本纪」介绍界面（右上角按钮 `白话：关 / 白话：开`）
   - 点击即可在「文言文」与「现代白话」之间切换，当前界面立即刷新。

2. **设置项（持久化）**
   - 设置界面新增开关「白话文模式」。
   - 勾选后随 `coh_settings` 存入 localStorage，下次打开自动生效。
   - 在设置中修改后，通过「返回」回到上一界面即应用。

> 模式状态在所有界面同步：选帝列表、本纪介绍、游戏事件、选项、AI 生成事件均会随开关切换。

---

## 二、覆盖范围

| 界面 / 文案 | 来源 | 白话处理方式 |
| --- | --- | --- |
| 皇帝列表「历史评价」 | 预置数据 | 预置白话层 `baihua.evaluation` |
| 本纪介绍「背景 / 评价 / 时代背景」 | 预置数据 | 预置白话层 `baihua.background` 等 |
| 历史事件「标题 / 描述 / 五选项 / 史实结局」 | 预置数据 | 预置白话层 `baihua.events[事件id]` |
| AI 实时生成的事件 / 后果 / 史官评 | 大模型 | 模式开启时由提示词直接要求「现代白话文」输出 |
| 未预译的预置文案（脚本未跑完时） | 预置数据 | 运行时按需补译并缓存（需联网 / 有 Key） |

- **选项倾向标签（hint）** 由原文语义推断，白话模式下仍按原文言推断，标签含义保持一致。
- 关闭模式时，所有文案立即恢复为原文言文。

---

## 三、数据 Schema

白话译文作为**预置白话层**存放在每位皇帝的 `baihua` 字段中（与原文并列，互不破坏），
位于 `data/emperors/0*.json` 的皇帝对象内：

```json
{
  "id": "xia_yu",
  "evaluation": "平水土，奠夏基",
  "background": "禹，姒姓，鲧之子……",
  "eraContext": "洪水初平……",
  "events": [ { "id": "xia_yu_e0", "title": "…", "description": "…", "choices": ["…"], "historicalOutcome": "…" } ],

  "baihua": {
    "evaluation": "治理水患、安定天下，奠定了夏朝的根基",
    "background": "禹，姓姒，是鲧的儿子……",
    "eraContext": "洪水刚刚被平定……",
    "events": {
      "xia_yu_e0": {
        "title": "涂山大会诸侯",
        "description": "禹接受禅让成为天下共主后……",
        "choices": ["处死防风氏以整肃号令……", "…", "…", "…", "…"],
        "historicalOutcome": "禹处死了防风氏……"
      }
    }
  }
}
```

要点：
- 预置白话按**皇帝 id + 事件 id** 索引，与 `normalizeEvent` 重建事件对象互不影响（白话存于皇帝层，不依赖事件对象本身）。
- `build_data.js` 合并数据时原样保留 `baihua`，无需改动打包流程。

## 四、批量补全翻译（推荐用于离线 / 全量覆盖）

游戏内置的文言文约 **234,000 字、262 位皇帝、1,866 个事件、9,325 个选项**。
手工预译全部成本高，故提供脚本 `tools/gen_baihua.py`，调用 OpenAI 兼容接口批量生成预置白话层。

### 1. 配置（三选一，环境变量）
```bash
export OPENAI_API_KEY="sk-..."                 # 必填
export OPENAI_BASE_URL="https://api.agnes-ai.cn/v1"   # 可选，默认内置端点
export OPENAI_MODEL="agnes-2.0-flash"          # 可选，默认
```

### 2. 运行
```bash
# 全量（断点续译：已完整翻译的皇帝自动跳过）
python tools/gen_baihua.py

# 试译前 3 位皇帝
python tools/gen_baihua.py --limit 3

# 指定模型 / 仅处理某文件
python tools/gen_baihua.py --model gpt-4o-mini --files 01-xia-shang-zhou-qin.json
```

### 3. 重新打包数据（必须）
```bash
node tools/build_data.js
```
脚本将带 `baihua` 的数据重新打包进 `data/emperors/coh_data.js`（游戏实际加载的文件）。

> 脚本仅用 Python 标准库（urllib），无需安装依赖；按皇帝分块翻译，带重试与间隔，可安全中断后继续。

## 五、运行时补译（按需、可缓存）

当白话模式开启、某段预置文案**尚未预译**、且当前**已配置可用 AI 凭据（联网）**时，
游戏会在渲染该段文案时异步请求一次翻译，并写入 `localStorage`（键 `coh_baihua_cache`）：
- 首次显示原文，译文返回后就地替换；
- 之后从缓存直接读取，**离线亦可用**。

适用场景：
- 脚本尚未跑完、个别皇帝未预译；
- AI 实时生成的事件（本就由提示词直接产出白话，无需补译）。

> 若处于「离线模式」、未配置任何 Key，或**已配置但凭据实际不可用**（例如 provisionUrl 下发服务不可达、内置密文无效、401/403 鉴权失败），运行时补译均不会触发：此时不会显示「白话文生成中…」占位，而是直接显示原文言文，已预译内容仍显示白话。游戏在启动及每次保存设置后会探查凭据真实可用性（`aiAvailable()` 以探查结果为准），因此全量离线体验需先运行第四节的脚本。

## 六、实现位置（供维护参考）

- `index.html`
  - 设置：`loadSettings / saveSettings / restoreBuiltin / loadSettingsToForm` 增加 `baihua` 布尔项；
    设置界面新增 `set-baihua` 开关。
  - UI：游戏与「本纪」界面右上角 `bh-toggle` / `bh-toggle-intro` 一键按钮。
  - 渲染接入：
    - `BK(emp, field)` —— 顶层字段（评价 / 背景 / 时代背景）白话解析；
    - `renderEvent / renderChoices / applyEventBaihua` —— 事件标题 / 描述 / 选项白话解析与异步替换；
    - `selectEmperor / selectDynasty` —— 本纪介绍与选帝列表接入 `BK`；
    - 预置历史事件路径（`buildHistoricalEvent / renderPreset`）写入 `currentEvent._ev` 以便按 id 取白话。
  - 运行时补译：`bhEventSync / bhFetchEventBaihua / bhFetchField / bhCache / bhEventKey`。
  - 一键切换：`toggleBaihua / persistBaihua / updateBhUI / rerenderCurrent`。
  - AI 提示词：模式开启时 `PROMPTS.user / PROMPTS.outcome` 追加「请用现代白话文撰写」指令。
- `tools/gen_baihua.py` —— 批量预译脚本（见第四节）。
- `data/emperors/0*.json` 与 `coh_data.js` —— 存放预置白话层。

---

## 七、质量约定

- 译文保持**原意、史实、人名地名**不变，语气贴合原文的庄重史书体，不增删情节、不改写续写。
- 选项译文与原文**顺序严格一致**（恰好 5 条）。
- 若译文不理想，可直接手工编辑对应 `baihua` 字段（或删除该字段让其回退/重新翻译），再 `node tools/build_data.js`。
