# 《择决千秋》随机事件系统（随机时局）设计文档 · GDD 片段

> 版本：v0.2（2026-08-06，方向修订：随机事件**主要为无决策自动改数值**）
> 范围：新增第 4 类事件源「随机时局」。纯机制 / 数据 / 数值，不涉及画面。
> 读者：实现该模块的开发者（陛下与狗噗）。
> 依赖：**必须先合入机制审查 B1（P0-1 五维失败链）**，见 §10。
> 方向说明：本版按产品决策将随机事件主模型定为「自动生效、无玩家抉择」，仅保留极少数可选轻抉择变体（见 §3.4）。设计张力与缓解见 §11。

---

## 0. 定位与现状基线

本系统是《优化设计文档》1.1/2.x 路线之外的**第 4 类事件源**，目标是：

1. 增加随机性（产品诉求）：外生冲击（灾异/祥瑞/时运）自动改写六维。
2. 顺手补掉《机制合理性专项审查》P2-2 的洞——当前 AI 日常事件真实感渗透率 **0%**，96% 的月是 AI 自由发挥。

| 项 | 当前值 | 来源 |
|----|--------|------|
| 事件源 | 历史（年份命中）/ 门控 major / 危机 / AI 日常 | `enterMonth` 审计 |
| AI 日常真实感渗透率 | ≈0% | 机制审查 P2-2 |
| 随机时局事件 | 无（本系统新增，v0.2 改为自动生效） | — |

**主模型变更（v0.1→v0.2）**：v0.1 要求随机事件必带 2–3 选项；v0.2 按决策改为**无抉择、自动生效**。代价是"选择有重量"被削弱，故引入**韧性调制**（§3.3）把能动性从"事件内反应"转移到"事件前积累"，并加严净漂移锁（§7）。

## 1. Fun Hypothesis 与 Design Pillars

**Fun Hypothesis（本子系统）**：玩家在已锚定史实的月份之外，会撞见符合时代的**外生冲击**（灾异/祥瑞/时运），它自动改写六维；但冲击的**幅度由玩家此前的积累决定**——随机性制造不可控，准备度决定代价。

**Design Pillars（不可妥协）**：

| # | 支柱 | 不可妥协的含义 |
|---|------|----------------|
| P1 | 时代真 | 随机池按 `eraTag` 分桶，只引用该时期真实制度/灾异/族群，绝不穿越 |
| P2 | 韧性调制 | 负面冲击幅度 = `base × 韧性系数(相关当前属性)`，准备度越高代价越低 → 无抉择但仍保有能动性 |
| P3 | 净漂移≈0 | 每个时期桶内 Σ(pᵢ·Δᵢ)≈0（逐维，按 base 计算），随机性只制造波动不制造通胀/崩盘 |
| P4 | 反簇集 | 两次 major 负面事件不背靠背；冷却防单事件刷屏 |

## 2. 系统总览（事件源矩阵）

| 事件源 | 优先级 | 是否带抉择 | 时代准确性 | 数据来源 |
|--------|--------|------------|------------|----------|
| 数值危机 | 1（最高） | 是（5） | 该维崩盘语境 | 预设/AI |
| 门控 major | 2 | 是（5） | 高（史实） | 预设 `events` |
| 中段定时炸弹 | 3 | 是（5） | 高（史实） | `midCrisisAnchors` |
| 年份命中历史 | 4 | 是（5） | 高（正史） | 预设 `events` |
| 科技阻力 | 5 | 是（5） | 高 | 预设 |
| **随机时局（本系统）** | **6** | **否（自动生效）** | **高（分桶策展）** | **`RANDOM_POOLS`** |
| AI 日常 | 7（最低） | 是（5） | **低（渗透率 0%）** | AI 自由生成 |

随机时局插入优先级 6：高于 AI 日常、低于一切史实/危机类。**它替换的是 AI 日常的份额，不挤占史实骨架。**

## 3. 数据 Schema

### 3.1 `emperor.eraTag`（每帝新增，262 帝批量补）

```jsonc
{ "id": "tang_xuanzong", "eraTag": "tang", /* …既有字段… */ }
```

`eraTag` 取值与朝代映射（一次性推导，写入即可）：

| eraTag | 覆盖朝代 |
|--------|----------|
| `shangzhou` | 夏、商、周 |
| `qinhan` | 秦、汉、新、三国 |
| `weijin` | 晋、南北朝、隋 |
| `tang` | 唐、五代十国 |
| `song` | 宋、辽、金、西夏 |
| `yuan` | 元 |
| `ming` | 明 |
| `qing` | 清 |

**理由**：随机池按"时期"而非"单帝"分桶。200+ 帝共享 8 个时期池，避免把事件按帝复制 N 倍；时代准确性本就是时期级属性。

### 3.2 `RANDOM_POOLS`（全局模块，定义一次）

新增数据模块（建议 `data/random_pools.js`，与 `coh_data.js` 同级加载）：

```js
window.COH_RANDOM_POOLS = {
  tang: [ /* 见 §6 */ ],
  song: [],
  // …其余 7 桶后续填充
};
```

### 3.3 单条随机事件结构（v0.2 自动生效）

```jsonc
{
  "id": "tang_locust",            // 桶内唯一
  "title": "蝗灾",                // 4–8 字
  "kind": "calamity",            // calamity(灾) / boon(祥瑞) / neutral(时运)
  "phase": ["壮年"],             // 可选：["即位","壮年","暮年"]；缺省=全期
  "major": false,                // true=重大冲击，幅度上限放宽（见 §8）
  "weight": 2,                   // 抽取权重（默认 1）
  "resilience": { "people": "people" }, // 负面冲击的"韧性键"：base 按该属性当前值缩放
  "description": "飞蝗蔽天，禾稼俱尽，饿殍载道。",
  "baseChanges": { "people": -7, "treasury": -2 }  // 预期值（在中位属性下即实际均值）
  // choices: 一般省略（自动生效）；极少数变体见 §3.4
}
```

字段约束（写进实现，缺省走默认）：
- `baseChanges` 仅含六维键；缺省键视为 0。
- 单项 `baseChanges` 绝对值 **≤ `RANDOM_STAT_CAP`**（normal）/ **≤ `RANDOM_STAT_CAP_MAJOR`**（major），超出截断。
- `resilience`：仅对 `baseChanges` 中**负值**生效（见 §4 `scaleByResilience`）；祥瑞类不缩放。
- `kind=calamity` 必须有 `resilience` 键对应其受冲击维，否则按无调制处理（告警）。

### 3.4 少数轻抉择变体（可选，非主线）

主线为自动生效；若需极少点缀，可给个别事件加 `choices`（2 个），但**默认不启用**，且启用时该事件不计入"无抉择"主体。v0.2 不预置此类，留作后续。

## 4. `enterMonth` 改造伪码（v0.2）

```js
function enterMonth(){
  state.pressure = computePressure(state);

  if (detectCrisis())                 return loadCrisis();        // 1 危机
  const gm = pickGatedMajor();        if (gm) return loadEvent(gm);// 2 门控 major
  if (pickMidCrisis())                return loadEvent(...);       // 3 定时炸弹
  const he = pickHistorical();        if (he) return loadEvent(he);// 4 年份命中
  if (pickTechResist())               return loadTechResist();     // 5 科技阻力

  // 6 日常 —— 插入随机时局掷骰（替换一部分 AI 日常）
  if (canFireRandom() && Math.random() < P_RAND) {
    return loadRandomEvent();
  }
  return loadAIDaily();  // 原逻辑（注入 _activeAnchor），随机未命中时的兜底
}

function canFireRandom(){
  const pool = COH_RANDOM_POOLS[state.emperor.eraTag];
  if (!pool || !pool.length) return false;
  if (state.lastRandomId && state.monthSinceRandom < RANDOM_COOLDOWN) return false;
  // 反簇集：上一次若是 major 负面，本月禁再出 major 负面
  if (state.lastRandomMajorNeg && Math.random() < ANTI_CLUSTER) return false;
  const phase = state.reignPhase;
  const cand = pool.filter(e => !e.phase || e.phase.includes(phase));
  return cand.length > 0;
}

function loadRandomEvent(){
  const phase = state.reignPhase;
  let cand = COH_RANDOM_POOLS[state.emperor.eraTag]
    .filter(e => (!e.phase || e.phase.includes(phase)) && e.id !== state.lastRandomId);
  if (!cand.length) cand = COH_RANDOM_POOLS[state.emperor.eraTag]
    .filter(e => e.id !== state.lastRandomId);
  const ev = weightedPick(cand);
  const changes = scaleByResilience(ev);          // 按韧性键缩放（仅负值）
  state.lastRandomId = ev.id;
  state.monthSinceRandom = 0;
  state.lastRandomMajorNeg = !!(ev.major && ev.kind === "calamity");
  state.currentEvent = Object.assign({ source:"随机时局", auto:true, applied:changes }, ev);
  renderRandomEvent(ev, changes);                 // 展示叙事 + 已生效数值（无选项）
  applyStatChanges(changes, ev.major ? "随机时局·重大" : "随机时局");
}

// 韧性调制：仅对负值，按相关属性当前值缩放；中位属性→scale=1（base 即预期均值）
function scaleByResilience(ev){
  const out = {};
  for (const k in ev.baseChanges){
    let v = ev.baseChanges[k];
    const rk = ev.resilience && ev.resilience[k];
    if (v < 0 && rk){
      const prep = (state.stats[rk] || 50) / 100;
      const scale = clamp(1.3 - 0.6 * prep, 0.6, 1.3);  // prep=0→1.3(放大), =1→0.7(减免30%)
      v = Math.round(v * scale);
    }
    out[k] = v;
  }
  return out;
}
```

`nextMonth` 中维护：`state.monthSinceRandom++`；`reignPhase` 重算（即位<15% / 壮年15–75% / 暮年>75%）。

## 5. 冷却 / 相位 / 反簇集 / 抽取

| 机制 | 行为 | rationale |
|------|------|-----------|
| 冷却 `RANDOM_COOLDOWN` | 同一事件 `K` 月内不重复 | 保"意外感"稀缺性，防单事件刷屏 |
| 相位门控 `phase` | 按 `reignPhase` 过滤池 | 暮年偏"疫病/继承"类冲击 |
| 反簇集 `ANTI_CLUSTER` | major 负面后本月禁再出 major 负面 | 防"连续天灾"把玩家瞬间推崩，违背 P4 |
| 加权抽取 `weight` | 按 `weight` 抽样 | 让标志性冲击（蝗/河）更常见 |
| 优先级 6 | 仅在一切史实/危机类之后 | 不挤占历史骨架，只替换 AI 日常 |

### 6.1 净漂移验算（按 base，等权，15 条）

逐维 Σ(baseChanges)（calamity 取负、boon 取正）：

| 维 | 合计 | 均值/事件 |
|----|------|-----------|
| 国库 T | (-2-4-3-5) + (3+4+3+2+3) = -14 + 15 = **+1** | +0.07 |
| 民心 P | (-7-5-3-2-4) + (8+3+2+8) = -21 + 21 = **0** | 0.00 |
| 军事 M | (-6-10) + (8+8) = -16 + 16 = **0** | 0.00 |
| 朝政 C | (-5) + 6 = **+1** | +0.07 |
| 健康 H | (-7-1) + 8 = **0** | 0.00 |
| 科技 Tech | 0 | 0.00 |

**结论**：加权等权下六维净漂移 `T+1 / P0 / M0 / C+1 / H0`，全部 ≤1/15 事件（≈0.07/事件），**通过 P3 锁**（阈值 ≤0.5/事件，见 §8）。Tech 恒为 0（随机时局不碰科技维，避免与科技树/穿越机制耦合）。

> ⚠️ `baseChanges` 是中位属性下的预期值。实际生效值经 `scaleByResilience` 缩放：高韧性维冲击被减免（最低 -30%），低韧性维被放大（最高 +30%）。所以**整池逐维期望漂移仍≈0，但单局波动被玩家准备度放大/缩小**——这正是"无抉择但保有能动性"的数学实现。

## 7. Sources / Sinks 平衡

- **Source（数值位移来源）**：随机事件自动 `baseChanges`（预设，确定性强；仅缩放系数依赖状态）。
- **Sink（回收）**：六维 `clamp(0,100)` + 危机自愈 + P0-1 失败链。
- **平衡铁律（P3）**：每个时期桶 Σ(pᵢ·baseChangesᵢ)≈0（逐维，按 base 计算）。因无玩家抉择补偿，**此锁比 v0.1 更严**。
- **验证口径**：对该桶做 Monte Carlo 500 次抽取（中位属性），看六维终态分布是否对称；单边漂移说明池子配比失衡（数据问题，非数值问题）。再跑一遍「高韧性 vs 低韧性」两态，确认缩放方向正确（高韧性→冲击更小）。

## 8. Tuning 参数表

| 参数 | 值 | rationale |
|------|----|-----------|
| `P_RAND` | [PLACEHOLDER·建议 0.25–0.35] | 史实月仅 ~3.7%；取 0.3 则约 29% 的月被时期准确随机事件占据，真实感渗透率 0%→30%+，且不挤占史实骨架。验证：随机月占比落 20–35%，不淹没史实月 |
| `RANDOM_STAT_CAP` | 10（normal，轻于历史 ±10 因更频繁） | 自动事件无抉择成本，单次幅度可略大于有抉择事件；[PLACEHOLDER·Monte Carlo 验证] |
| `RANDOM_STAT_CAP_MAJOR` | 14（major） | 重大冲击允许更大，但仍受 clamp；[PLACEHOLDER] |
| `RANDOM_COOLDOWN` | 6 月 | 防连刷，保意外感稀缺性 |
| `ANTI_CLUSTER` | 0.6（major 负面后本月禁再出 major 负面概率） | 防"连续天灾"秒崩，违背 P4 |
| 韧性系数 `1.3 - 0.6·prep` | clamp[0.6, 1.3] | prep=中位(0.5)→1.0（base=预期）；prep=1→0.7（减免30%）；prep=0→1.3（放大30%）。让准备度转化为真实代价差 |
| 相位划分 | 即位<15% / 壮年15–75% / 暮年>75% | 按在位进度，暮年偏疫病/继承类 |

所有未标 rationale 的数字标 `[PLACEHOLDER · 验证路径：Monte Carlo 500 局，看随机月占比与六维终态分布是否落目标区间]`。

## 9. 与既有系统的耦合点

| 耦合点 | 行为 | 注意 |
|--------|------|------|
| `applyStatChanges` | 复用既有数值应用 + clamp；major 用 `RANDOM_STAT_CAP_MAJOR` | 不新增一套 clamp，避免 P1-1 三套数字再打架 |
| 危机触发 | 自动事件把某维压到 ≤10 → 下月 `detectCrisis` 切危机事件 | 与危机自愈叠加，见 §11 |
| 科技树 | 本系统不碰 `tech`（§6.1 恒 0） | 避免与穿越机制耦合 |
| AI 日常 | `P_RAND` 命中时**替换** AI 日常，不叠加 | 未命中才走 AI，保证 AI 月占比随 `P_RAND` 下降 |

## 10. 依赖与落地顺序

| 批次 | 项 | 理由 |
|------|----|------|
| **先 B1（P0-1）** | 五维失败链（预警→恶化→崩盘） | **比 v0.1 更紧迫**：自动负面事件无抉择缓冲，若 5 维归零仍被危机自愈奶回，则随机冲击零代价、纯噪声 |
| 本系统 P1 | `eraTag` 批量补 262 帝 + `RANDOM_POOLS` 模块 | 纯数据，低风险 |
| 本系统 P2 | `enterMonth` 掷骰 + `scaleByResilience` + 冷却/相位/反簇集 | 代码改动，对齐 §4 |
| 本系统 P3 | `tang` 桶 15 事件试点 + 漂移验算 | 验证机制不通胀 |
| 后续 | 其余 7 桶按同模板填充 | 每桶交付前跑 §6.1 验算 |

## 11. 风险备案（方向已由产品决策确定，此处仅记录冲突与缓解）

**冲突 1：削弱"选择有重量"核心卖点。**
自动改数值 = 玩家对该事件无反应权，易沦为旁观者。
**缓解**：韧性调制（§3.3/§4）——冲击幅度由相关属性当前值决定，玩家"此前是否积谷、练兵、修河"直接转化为代价差。能动性从"事件内反应"上移到"事件前积累"。

**冲突 2：自动负面事件 + 危机自愈 = 免费噪声（pre-B1）。**
若 P0-1 未落地，某维被压到 ≤10 → 危机事件自愈奶回 → 随机冲击零代价。
**缓解**：§10 强制 B1 先行；B1 落地后 5 维可致死，随机负面才真正有 teeth。

**冲突 3：连续重大负面可能瞬间推崩。**
**缓解**：反簇集（§5 `ANTI_CLUSTER`），major 负面后本月禁再出 major 负面。

**冲突 4：桶过大/过频 → 随机感盖过历史感。**
**缓解**：`P_RAND` 上限 0.35，且不挤占史实月（优先级 6）；桶规模建议 ≥12 事件以防重复感。

**残余风险（诚实标注）**：即便有韧性调制，纯自动模型在"事件内"零能动性。若实测玩家反馈"像看戏"，退路是启用 §3.4 轻抉择变体（个别事件补 2 选项）作为点缀，不必全量回退。

## 12. 验收口径

| 指标 | 达标线 |
|------|--------|
| 真实感渗透率（随机月 / 总月，且为时期准确） | ≥25%（原 0%） |
| 单桶净漂移（按 base，T/P/M/C/H 任一项 |均值|） | ≤0.5/事件（本试点 +0.07，过） |
| 韧性方向正确 | 高韧性维实际冲击 < 低韧性维（Monte Carlo 两态验证） |
