# Choice of History · 科技树系统设计

> 一套从上古到星际、覆盖 9 大分支 × 14 个科技时代、共 **1134** 个不重复节点的宏大科技树。
> 玩家以「科技属性点数」解锁并升级节点，自由度极高；各朝代皇帝开局即带符合其时代特征的**预置科技树**；
> 系统能识别玩家拥有的**超前（越代）科技**，并据衰减模型正确计算其对六维生涯属性的增益，输出 AI 可读档案。

---

## 1. 设计目标与约束

| 约束 | 实现方式 |
|---|---|
| ≥1000 节点且不重复 | 分支(9)×时代(14)×轨道(9)=1134；生成器强制全局名称唯一性校验 |
| 覆盖上古→未来全部时代 | 14 级科技时代：蒙昧石器时代 → 星际奇点 |
| 全面的分支与节点 | 9 大分支，每分支 9 条「轨道」，每条轨道贯穿 14 时代 |
| 玩家用科技点数解锁/升级 | 每节点有 `cost.base`(解锁首级) 与 `cost.perLevel`(逐级递增)，`maxLevel` 1–5 |
| 不每朝从零开始 | `tech_presets.json` 为各朝代预置已加点科技树作为初始状态 |
| AI 识别超前科技并正确计算增益 | `tech_engine` 计算 `techProfile`，含越代清单、衰减增益、`aiSummary` 文本 |

---

## 2. 总体架构

```
data/
  tech_tree.json      # 1134 节点 + meta(分支/时代/属性映射)
  tech_presets.json   # 各朝代时代预设（皇帝初始科技树）
  tech_tree_ui.html   # 可嵌入的浏览/解锁/升级面板（演示+集成用）
tools/
  gen_techtree.py     # 生成器（策展数据 + 校验，可重跑）
  tech_engine.js      # 浏览器/Node 计算引擎（超前科技识别+增益+AI档案）
  tech_engine.py      # Python 参考实现 + 演示（逻辑与 JS 一致）
docs/
  科技树系统设计.md    # 本文
```

三层：**数据层**（JSON）→ **引擎层**（tech_engine，纯函数 `compute`）→ **表现层**（UI / 游戏内面板）。

## 4. 节点 Schema

```json
{
  "id": "agri_03_00",
  "name": "代田法",
  "branch": "agri", "branchName": "农政", "track": "耕作",
  "age": 3, "ageName": "铁器春秋", "era": "春秋战国",
  "desc": "农政·铁器春秋：代田法。耕织为本，仓廪实而知礼节。",
  "prereq": ["agri_02_00"],          // 同分支上一时代同轨道；根节点为空
  "maxLevel": 3,                      // 时代越高上限越高(3→4→5)
  "cost": {"base": 5, "perLevel": 1},// 解锁首级5点，之后每级+1
  "bonusPerLevel": {"treasury": 1, "people": 1}, // 每级属性增益
  "special": "yield",                // 特殊增益键
  "specialAttr": "treasury"          // 特殊增益映射到的六维属性
}
```

**前置关系（DAG）**：每节点仅依赖「同分支上一时代同轨道」，形成清晰的树状依赖，无环。

## 5. 解锁 / 升级 与 科技点数

- 玩家持有一池「科技点数」（可由 `tech` 属性、事件抉择、研究类特殊增益产生）。
- 解锁首级花费 `cost.base`，之后每升一级 `+cost.perLevel`，上限 `maxLevel`。
- 前置未满足（上一时代同轨道 <1 级）则锁定，不可点击。
- 越代节点（age > 当前皇帝 eraLevel）同样可解锁——这是「穿越者」自由度的核心。

## 6. 朝代预设（皇帝初始科技树）

`tech_presets.json` 按 `朝代 → {eraLevel, eraName, techCount, techs:{id:level}}` 存储：

- `eraLevel` 由 `DYNASTY_ERA` 映射（如 秦=3，唐=5，明=7，清=8）。
- 预设规则：核心轨道(前3条)在 age≤2 时满级、age≤eraLevel−1 时 2 级、其余 1 级；
  非核心轨道仅在 age≤eraLevel−2 时开放 1 级；再叠加各朝代「标志科技」（书同文/科举/活字/郑和宝船…）强化。
- 结果：夏开局 27 项 → 清 543 项 → 终末 1026 项，呈平滑的时代梯度，**绝非从零开始**。

## 7. 超前（越代）科技识别与增益计算

`tech_engine.compute(emperor, ownedTechs)` 返回 `techProfile`：

1. **识别**：对每个已拥有节点，`gap = node.age − emperor.eraLevel`；`gap>0` 即超前科技。
2. **衰减增益**：`factor = aheadDamp(gap) = max(0.15, 1 − 0.18·gap)`。
   差距越大落地效率越低，但永不为 0（知识本身即有价值）。例：领先1代=82%，3代=46%，11代=15%。
3. **属性增益**：`属性加成 += 节点每级增益 × 等级 × factor`，主/次属性与 `special→属性` 一并计入，最终六维四舍五入。
4. **AI 档案**：`profile.aiSummary` 与 `profile.ahead`（清单+落地效率+实际四舍五入增益）供大语言模型直接读取，
   使 AI 既能**识别**玩家所拥越代科技，又能**正确计算**其对生涯属性的真实增益（含「近乎为零，仅余名而无实」的诚实边界）。

六维增益可直接叠加到游戏既有 `initStats`（`treasury/people/military/court/health/tech`，0–100），
与 `index.html` 现有「科技可越时代」「科技阻力事件」机制天然衔接。

## 8. 接入现有游戏（index.html）建议

1. 在游戏初始化时：`owned = engine.presetFor(emperor.dynasty)` 作为开局科技树。
2. 每个结算周期：`profile = engine.compute(emperor, owned)`；将 `profile.attrBonus` 叠加到 `state.stats`（注意 cap 0–100）。
3. 科技阻力事件阈值由 `initStats.tech+20` 改为参考 `profile.attrBonus.tech`（越代科技拉高阈值，更合理）。
4. 事件生成 prompt（现有 `buildPrompt`）追加 `profile.aiSummary`，让 AI 据玩家越代科技生成后果与叙事。
5. 科技点数：把 `initStats.tech` 视作「科技潜力」，由事件/研究转化为可花费点数；UI 用 `tech_tree_ui.html` 风格内嵌。

## 9. 扩展示例

- **新增时代**：在 `gen_techtree.py` 的 `AGES` 追加，并为各分支在该时代补 9 个名称 → 重跑生成器。
- **新增分支**：在 `BRANCHES` 追加（含 `attrs`/`tracks`/`specials`），并在 `BRANCH_NAMES` 补 14×9 名称、`SPECIAL_TO_ATTR` 补映射。
- **新增朝代预设**：在 `DYNASTY_ERA` 与 `SIGNATURE` 追加即可，生成器自动产出。

> 校验：生成器内置「节点数≥1000 / 名称全局唯一 / DAG 无环 / 前置存在 / 预设引用合法」断言，失败即报错。
